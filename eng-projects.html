Format

How each project works

  1. The brief: a ticket with a user story and acceptance criteria, and a diagram of the parts.
  2. A starter to download: a project folder with sample data, the tests, and TODO milestone N comments where you write code. It runs from the start; each milestone makes it do more.
  3. Four to six milestones, each with what to write and why, the checkpoint command and its real output, a live run, and an "If it breaks" box.
  4. A checker: uv run check.py 3 says which milestones work. Claude is faked in its tests, so checking is free, offline and instant.
  5. An eval you run as you go, so you see whether each change made the tool better.
  6. Stretch goals, a README template, a CV line and interview points, so the project is ready to show.

Help

When you're stuck

Read the checker

It shows the first check that fails and a hint. The test's name says what it expects; open the test file to see the exact case.

Open the hints

Every milestone has two hints, then the solution. Try each hint for ten minutes before opening the next.

Compare with the finished code

The finished projects are in the projects folder on GitHub, tested on every change. The starters are built from them.
