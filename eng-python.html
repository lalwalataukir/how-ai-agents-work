1 · Values and variables

    
Five kinds of value cover most AI code

    
A variable is a name for a value. The = sign means "make this name point to this value", not "equals". Most of what flows through an AI app is text: prompts, answers and web pages, all .

  

  
Try it in uv run python
topic = "Large language model"    # str: text, in quoteswords = 120                       # int: a whole numberprice = 3.0                       # float: a number with a decimal pointdone = False                      # bool: True or Falseurl = None                        # None: no value yetprint(f"{topic}: {words} words")  # prints  Large language model: 120 words

  
The  on the last line is how you'll build prompts: write the text, and put each variable in {…}. Anything after # is a comment, for people only; Python ignores it.







  

    
2 · Lists and dicts

    
The two shapes all AI data comes in

    
A  keeps items in order. A dict looks values up by name. Put dicts inside a list and you have the exact shape you'll send to an LLM in E3: a conversation, as a list of messages.

  

  
Try it in uv run python
topics = ["agents", "RAG", "evals"]   # list: items in ordertopics[0]                             # "agents" (counting starts at 0)topics.append("tools")                # add to the end note = {"title": "RAG", "words": 42}  # dict: values looked up by keynote["title"]                         # "RAG"note["words"] = 50                    # change a valuenote.get("url", "none")               # "none", because there is no "url" key messages = [                          # a list of dicts: the shape of an LLM call    {"role": "user", "content": "What is RAG?"},]

  

    
Square brackets [ ]
Make a list, and read from both lists and dicts: topics[0] is the first item, note["title"] the value for "title".

    
Curly braces { }
Make a dict of key: value pairs. Keys are usually strings. Asking for a key that isn't there raises KeyError, so use .get() when it might be missing.

3 · Functions and loops

    
Name a piece of work, then repeat it

    
A  wraps a few lines under a name, so you can run them again with different inputs. A  runs the same lines for each item in a list. Agents are built from both: an agent is a loop that calls functions (tools) until the job is done.

  

  
Try it in uv run python
def word_count(text):    """Return how many words are in text."""    return len(text.split()) for topic in ["agents", "RAG", "evals"]:    if topic == "RAG":        print("found it:", topic)    else:        print("not this one:", topic) print(word_count("Agents call tools in a loop"))  # 6

  
Indentation is part of the code. The four spaces at the start of a line show what's inside the function, the loop or the if. A colon : ends the line above every indented block. VS Code indents for you when you press Enter after a colon.







  

    
4 · Files and JSON

    
JSON is how programs pass data around

    
Web APIs answer in JSON, LLMs can be asked to reply in it (E4), and it's the simplest way to save data between runs. Python's json module turns JSON text into dicts and lists, and back.

  

  
Try it in uv run python
import jsonfrom pathlib import Path note = {"title": "RAG", "words": 42}path = Path("notes.json")path.write_text(json.dumps([note], indent=2))  # Python -> JSON text -> filenotes = json.loads(path.read_text())          # file -> JSON text -> Pythonprint(notes[0]["title"])                      # RAG

5 · Errors

    
Handle the errors you expect, let the rest show

    
When something goes wrong while the program runs, Python raises an . Unless you handle it, the program stops and prints a traceback (you learned to read those in E1). AI code meets errors constantly: networks fail, APIs say no, and models return something unexpected.

  

  
Try it in uv run python
note = {"title": "RAG"}try:    words = note["words"]except KeyError:    words = 0           # a missing count is fine here: use 0print(words)            # 0

  

    

      
ExceptionTypical cause

      
        
KeyErrorAsking a dict for a key it doesn't have

        
IndexErrorAsking for item 5 of a list with 3 items

        
TypeErrorMixing types, such as "words: " + 42 (use an f-string)

        
ValueErrorThe right type but a bad value, such as int("ten")

        
FileNotFoundErrorOpening a file that isn't there, often the wrong folder

      
    

  

  
Catch only the errors you expect and know what to do about. Catching everything hides real bugs: the program keeps running with wrong data, and you never see the traceback that would have told you why.







  

    
6 · Calling a web API

    
Ask a server for data, get JSON back

    
A web API is a URL that answers programs instead of people. You send a request, and it sends back a  and a body, usually JSON. The httpx package does the sending.

  

  
Try it after uv add httpx (lab step 3)
import httpx url = "https://en.wikipedia.org/api/rest_v1/page/summary/Python_(programming_language)"headers = {"User-Agent": "research-assistant/0.1 (you@example.com)"}response = httpx.get(url, headers=headers, timeout=10)print(response.status_code)   # 200 means OKdata = response.json()        # the body, as a dictprint(data["title"])          # Python (programming language)

  

    

      
StatusMeansWhat your code should do

      
        
200OKRead the body

        
400Bad request: something in what you sent is wrongFix the request; retrying won't help

        
401 / 403Not allowed: missing or wrong key, or blockedCheck the key or 

        
404Not foundReport it and move on

        
429Too many requestsWait, then retry

        
500 / 503The server has a problemWait, then retry a few times

      
    

  

  
An LLM is a web API too. In E3 you'll send a request with your messages as JSON and your API key in a header, and get the model's answer back as JSON. The SDK wraps it in one function call, but underneath it's what you do here, including 429s and timeouts.

    wiki_notes.py
    """E2 lab: save short Wikipedia summaries as notes. Run it with one or more topics:    uv run wiki_notes.py "Large language model" "Prompt engineering""""import jsonimport sysfrom datetime import datefrom pathlib import Pathfrom urllib.parse import quote import httpx API_URL = "https://en.wikipedia.org/api/rest_v1/page/summary/"# Wikipedia asks every script to say who it is. Put your email or GitHub link here.HEADERS = {"User-Agent": "research-assistant/0.1 (you@example.com)"}NOTES_FILE = Path("notes.json")  def fetch_summary(topic):    """Ask Wikipedia for a short summary of one topic. Returns the JSON as a dict."""    url = API_URL + quote(topic.replace(" ", "_"))    response = httpx.get(url, headers=HEADERS, timeout=10, follow_redirects=True)    response.raise_for_status()  # turns answers like 404 into an error    return response.json()  def make_note(data):    """Keep only the fields we need from Wikipedia's answer."""    return {        "title": data["title"],        "description": data.get("description", ""),        "summary": data["extract"],        "url": data["content_urls"]["desktop"]["page"],        "saved_on": date.today().isoformat(),    }  def load_notes():    """Read the notes saved so far, or start with an empty list."""    if NOTES_FILE.exists():        return json.loads(NOTES_FILE.read_text(encoding="utf-8"))    return []  def save_notes(notes):    NOTES_FILE.write_text(json.dumps(notes, indent=2, ensure_ascii=False), encoding="utf-8")  def already_saved(notes, title):    for note in notes:        if note["title"] == title:            return True    return False  def main(topics):    notes = load_notes()    for topic in topics:        try:            data = fetch_summary(topic)        except httpx.HTTPStatusError as error:            print(f"Error: {topic}: Wikipedia answered {error.response.status_code}")            continue        except httpx.RequestError as error:            print(f"Error: {topic}: could not reach Wikipedia ({type(error).__name__})")            continue         if data.get("type") == "disambiguation":            print(f"Skipped: {topic} has several meanings. Try a more specific title.")            continue         note = make_note(data)        if already_saved(notes, note["title"]):            print(f"Skipped: {note['title']} is already saved")            continue         notes.append(note)        words = len(note["summary"].split())        print(f"Saved: {note['title']} ({words} words)")     save_notes(notes)    print(f"Notes in {NOTES_FILE}: {len(notes)}")  if __name__ == "__main__":    topics = sys.argv[1:]  # everything typed after the file name    if not topics:        topics = ["Large language model"]    main(topics)
    • fetch_summary builds the web address, asks Wikipedia, and turns the JSON answer into a dict.
    • make_note keeps the five fields you need from that dict.
    • load_notes and save_notes read and write notes.json.
    • main loops over your topics. Each error is caught and reported, so one bad topic doesn't stop the rest.
    • if __name__ == "__main__": runs main only when you run this file directly, which lets later modules import its functions.

3 common beginner mistakes in AI code

  

  

    
1
Assuming the shape of the data

      
What it looks like
KeyError: 'description' on the one page that has no description, after twenty that worked.

      
Fix
Print the JSON once and look at it. Use .get() for fields that can be missing.

    
2
Network calls with no timeout or error handling

      
What it looks like
The script hangs for minutes on a slow server, or one bad topic crashes a run of fifty.

      
Fix
Always pass a timeout, call raise_for_status(), and handle errors per item so one failure doesn't stop the rest.

    
3
Pasting code you can't explain

      
What it looks like
It works today. Next week it breaks and you can't tell which of the forty pasted lines matters.

      
Fix
Don't commit a line you can't explain. Ask the assistant to explain it, or change it and see what breaks.
