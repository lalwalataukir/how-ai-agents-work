Tool calling: let the model ask your code for help

On its own, a model can only write text from what it learned in training. let it ask your code to do things, such as searching, reading a page or saving a note, and then use the results. This module covers how to describe tools, how to write the by hand, and how to keep it safe and affordable. It's the "act and observe" from module 1, in code. You'll build a research assistant that searches Wikipedia, reads pages and cites them.

1 · What a tool is

The model asks; your code acts

A model can't browse the web, read your files or run code. It can only write. Tool calling gives it a way to write a request ("run search_wikipedia with these words") that your code carries out.

  1. You describe the tools in the request: a name, what it does, and what arguments it takes.
  2. The model replies with a block instead of an answer, and stop_reason is "tool_use".
  3. Your code runs the function with those arguments, or refuses to.
  4. Your code sends back a tool_result, and the model carries on, perhaps asking for another tool, until it answers.

Nothing runs unless your code runs it. The model only ever produces text. That makes your code the place for every safety rule: which tools exist, which arguments are allowed, and what needs a person's approval.

2 · Defining tools

The description is a prompt

Each tool is a dict with a name, a description and an input schema, the same JSON schema idea as E4. The model decides when and how to use a tool from its description alone, so write it as carefully as a prompt.

One tool definition
{    "name": "read_page",    "description": "Read the summary of one Wikipedia page. "                   "Use an exact title from search_wikipedia.",    "input_schema": {        "type": "object",        "properties": {"title": {"type": "string", "description": "The exact page title"}},        "required": ["title"],        "additionalProperties": False,    },    "strict": True,}
Weak descriptionStrong description
Reads a page.Read the summary of one Wikipedia page. Use an exact title from search_wikipedia.
Search tool.Search English Wikipedia. Returns up to 5 page titles, each with a one-line description. Use it to decide which pages to read.
query: stringquery: a few search words, such as "retrieval augmented generation"

"strict": True turns on : the API guarantees the arguments match the schema, so args["title"] is always there. Fewer, clearer tools work better than many overlapping ones; module 8 explains why each definition also costs tokens on every call.

3 · The loop

Call, run, send back, repeat

One question can take several model calls: search, read, read again, answer. The loop keeps going while stop_reason is "tool_use" and stops when the model answers.

The loop, simplified (the lab adds a call limit)
messages = [{"role": "user", "content": question}]while True:    response = client.messages.create(model=MODEL, max_tokens=4000, tools=TOOLS, messages=messages)    messages.append({"role": "assistant", "content": response.content})    if response.stop_reason != "tool_use":        break                                   # the model answered    results = []    for block in response.content:        if block.type == "tool_use":            text, failed = run_tool(block.name, block.input)            results.append({"type": "tool_result", "tool_use_id": block.id,                            "content": text, "is_error": failed})    messages.append({"role": "user", "content": results})   # all results, one message

Keep the whole reply

Append response.content as the assistant message, tool_use blocks and all. The model needs to see what it asked for.

One result per request

Every tool_use gets a tool_result with the same tool_use_id. Miss one and the next call fails with a 400.

All results together

With , run them all and send every result in one user message, not one message each.

4 · Running tools safely

Your code is the guard

Tools turn a model's words into actions. Module 9 covers how attackers exploit that. These habits start in the very first tool you write.

HabitIn the lab code
Report failures, don't crashrun_tool returns the error text with , and the model tries a different title
Only run tools you definedAn unknown tool name gets an error, never a guess
Time limits on everythingtimeout=10 on every web request
Cap the loopA , MAX_CALLS = 8, stops a confused run
Read-only firstBoth tools only read. Tools that write, send or delete need a person's approval (E10)
Treat tool output as dataPage text could contain instructions. The system prompt and tags keep them in their place (module 9)

Never pass a model's arguments to eval, a shell command or an open-ended URL fetch. Give it narrow tools that can only do what you intend.

5 · What loops cost

Every call re-sends everything so far

The loop is a conversation that grows with each tool result. Call 4 carries the question, every tool request and every page the model has read. That's why one tool-using question costs several times a simple chat turn.

Short tool results

Return summaries and the fields the model needs, not whole pages. read_page returns a summary, not the full article.

Fewer, better calls

Good descriptions mean fewer wrong guesses. A search tool that returns descriptions saves reading the wrong pages.

Measure it

The lab prints the calls and tokens for every question. Module 8 adds caching, which cuts the cost of everything re-sent.

6 · By hand or with a framework

Write the loop once, then choose

The loop you write in this lab is about 25 lines. Frameworks run it for you: the Anthropic SDK has a tool runner, and LangChain and LangGraph (modules 3 and 4, and E7) add state, retries and approval steps.

Writing it by hand once means you know what any framework is doing underneath: which messages go back and forth, where errors go, and why costs grow. When a framework-built agent misbehaves, that's what you'll need to debug it. In E7 you'll rebuild this bot in LangGraph and compare.

    research_bot.py
    """E5 lab: a research bot that searches Wikipedia with tools and cites what it read. Run it with:    uv run research_bot.py "Who coined the term artificial intelligence, and when?""""import jsonimport sysfrom urllib.parse import quote import anthropicimport httpxfrom dotenv import load_dotenv load_dotenv() MODEL = "claude-haiku-5-5"PRICE_IN, PRICE_OUT = 0.10, 0.50  # dollars per million tokens, for this modelHEADERS = {"User-Agent": "research-assistant/0.1 (you@example.com)"}  # your email, as in E2MAX_CALLS = 8  # a safety limit: at most this many model calls per questionSYSTEM = (    "You are a research assistant. Use the tools to find facts on Wikipedia before you answer. "    "Answer in at most 150 words. After each fact, cite the page it came from as [Page title]. "    "If the pages you read don't answer the question, say so.") TOOLS = [    {        "name": "search_wikipedia",        "description": "Search English Wikipedia. Returns up to 5 page titles, each with a one-line "                       "description. Use it to decide which pages to read.",        "input_schema": {            "type": "object",            "properties": {"query": {"type": "string", "description": "A few search words"}},            "required": ["query"],            "additionalProperties": False,        },        "strict": True,  # the model's arguments always match this schema    },    {        "name": "read_page",        "description": "Read the summary of one Wikipedia page. Use an exact title from search_wikipedia.",        "input_schema": {            "type": "object",            "properties": {"title": {"type": "string", "description": "The exact page title"}},            "required": ["title"],            "additionalProperties": False,        },        "strict": True,    },] client = anthropic.Anthropic()  def search_wikipedia(query):    response = httpx.get("https://en.wikipedia.org/w/rest.php/v1/search/page",                         params={"q": query, "limit": 5}, headers=HEADERS, timeout=10)    response.raise_for_status()    return [{"title": page["title"], "description": page.get("description") or ""}            for page in response.json()["pages"]]  def read_page(title):    url = "https://en.wikipedia.org/api/rest_v1/page/summary/" + quote(title.replace(" ", "_"))    response = httpx.get(url, headers=HEADERS, timeout=10, follow_redirects=True)    response.raise_for_status()    data = response.json()    return {"title": data["title"], "summary": data["extract"], "url": data["content_urls"]["desktop"]["page"]}  def run_tool(name, args):    """Run one tool call. Returns the text to send back, and whether it failed."""    try:        if name == "search_wikipedia":            result = search_wikipedia(args["query"])        elif name == "read_page":            result = read_page(args["title"])        else:            return f"There is no tool called {name}.", True    except httpx.HTTPStatusError as error:        return f"Wikipedia answered {error.response.status_code}. Check the title and try again.", True    except httpx.RequestError:        return "Could not reach Wikipedia.", True    return json.dumps(result), False  def research(question):    """The tool-use loop: call the model, run the tools it asks for, send back the results, repeat."""    messages = [{"role": "user", "content": question}]    tokens_in = tokens_out = 0    for call in range(1, MAX_CALLS + 1):        response = client.messages.create(            model=MODEL, max_tokens=4000, system=SYSTEM, tools=TOOLS, messages=messages,        )        tokens_in += response.usage.input_tokens        tokens_out += response.usage.output_tokens        messages.append({"role": "assistant", "content": response.content})         if response.stop_reason != "tool_use":  # no more tools wanted: this is the answer            cost = (tokens_in * PRICE_IN + tokens_out * PRICE_OUT) / 1_000_000            print(f"  [{call} model calls, {tokens_in} tokens in, {tokens_out} out, ${cost:.5f}]\n")            answer = "".join(block.text for block in response.content if block.type == "text")            if response.stop_reason != "end_turn":                answer += f"\n(Stopped early: {response.stop_reason})"            return answer         results = []  # one tool_result for every tool_use, all sent back in one message        for block in response.content:            if block.type == "tool_use":                print(f"  -> {block.name}({json.dumps(block.input)})")                text, failed = run_tool(block.name, block.input)                results.append({"type": "tool_result", "tool_use_id": block.id, "content": text, "is_error": failed})        messages.append({"role": "user", "content": results})    return f"Stopped after {MAX_CALLS} model calls without a final answer."  if __name__ == "__main__":    question = " ".join(sys.argv[1:]) or input("Question: ")    print(research(question))
    • TOOLS is what the model sees: names, descriptions and input schemas. It never sees your Python.
    • search_wikipedia and read_page are ordinary functions, like E2's.
    • run_tool picks the function by name and turns failures into error text the model can read.
    • research is the loop: call the model, run what it asks for, send back one tool_result per tool_use, and stop at end_turn or MAX_CALLS.

Keep this

One-page cheat sheet

Describe tools → model asks with tool_use → your code runs it → send tool_result → repeat until end_turn or the call limit.

A tool

  • name, description, input_schema
  • "strict": True for guaranteed arguments
  • Description says what, when and how
  • Few, narrow, read-only first

The loop

  • Append response.content
  • For each tool_use: run, then tool_result with its tool_use_id
  • All results in one user message
  • Stop at end_turn or MAX_CALLS

Safety and cost

  • Errors go back with is_error
  • Timeouts on every tool
  • Approval before tools that change things
  • Short results; log calls and tokens

Learn from others

3 common tool-calling mistakes

1

Vague tool descriptions

What it looks like
The model calls the wrong tool, guesses page titles, or never uses the tool that would have answered the question.
Fix
Say what the tool does, when to use it, and what good arguments look like, with an example.
2

A loop with no limit

What it looks like
A tool keeps failing, the model keeps retrying, and one question makes 40 calls.
Fix
Cap calls per question, send errors back clearly, and log every call so you can see what happened.
3

Tools with too much power

What it looks like
A "run any command" or "fetch any URL" tool, which an instruction hidden in a web page can turn against you.
Fix
Narrow tools that can only do what you intend, read-only by default, with approval for anything that changes or sends data.
