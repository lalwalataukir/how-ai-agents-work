Your dev setup: terminal, Python, VS Code and git

    1 · The terminal

    Eight commands cover most of what you'll type

    The terminal is a text window for giving your computer instructions. It looks old-fashioned, but it's faster than clicking, it works the same on every computer, and almost every AI tool is installed and run from it.

    The terminal is always "in" one folder, the . Commands look for files there. Most beginner errors are a command run in the wrong folder, so pwd and ls are the two you'll use most.

    CommandWhat it doesWindows PowerShell
    pwdPrint the folder you're inpwd
    lsList the files and folders herels
    cd codeGo into the folder codecd code
    cd ..Go up one foldercd ..
    cd ~Go to your home foldercd ~
    mkdir notesMake a new foldermkdir notes
    cat hello.pyShow what's in a filecat hello.py
    touch notes.mdMake an empty fileni notes.md

    Paths

    A is a file's address. ~ means your home folder and .. the folder above. cd ../Downloads means "up one, then into Downloads".

    Shortcuts

    Tab finishes a name for you. ↑ repeats your last command. Ctrl + C stops a program that's still running.

    Spaces matter

    A space separates a command from what it acts on. A folder name with a space needs quotes: cd "My Projects". Use names without spaces for code.

    2 · Python and uv

    Python is the language; uv runs the project

    Most AI engineering is written in Python: the model providers' SDKs, LangChain and LangGraph, evaluation tools, data work. You'll learn the parts you need in E2. First you need a clean way to install it and keep each project tidy.

    The problem

    Every project uses : code other people wrote, such as httpx for web requests. Different projects need different versions, and installing everything into one shared Python breaks things sooner or later.

    The fix

    Give each project its own , a private .venv folder of packages. creates it and uses it for you, so you rarely think about it.

    uv commandWhat it doesWhen you use it
    uv initMakes the folder a Python project, with a Once, at the start
    uv add httpxInstalls a package and records it in pyproject.tomlWhenever you need a new package
    uv run hello.pyRuns your file with the project's Python and packagesEvery time you run code
    uv run pythonOpens interactive Python, to try lines one at a timeWhen experimenting (E2)

    You'll see pip in tutorials. pip install httpx is the older way to install a package. In your project, use uv add httpx instead, and uv run rather than python. They do the same job, with less to go wrong.

    3 · VS Code

    One window for files, code and terminal

    VS Code is a free code editor. It colours your code, points out mistakes as you type, and has a terminal built in, so you don't switch windows.

    Open the folder, not a file

    File → Open Folder on your project. The file list, search and terminal then all work from the project folder.

    Use its terminal

    Terminal → New Terminal. It opens in the project folder, which avoids the most common error, and it signs you in to GitHub when you push.

    Save before you run

    A dot on a file's tab means unsaved changes. Cmd/Ctrl + S saves. Or turn on File → Auto Save.

    Other editors such as Cursor or PyCharm work too. The track uses VS Code because it's free and its built-in terminal and GitHub sign-in are simple.

    4 · git and GitHub

    Save points on your laptop, and a copy online

    git keeps a history of your project. Each is a snapshot with a message, so you can see what changed and go back when an experiment goes wrong. GitHub stores a copy online, which is also your portfolio.

    1. Edit files in VS Code and save them.
    2. git add . chooses what goes in the next snapshot (the dot means "everything changed here").
    3. git commit -m "message" saves the snapshot on your laptop. Write what changed: "Add Wikipedia notes script".
    4. git push sends your new commits to GitHub.

    Clone once, push often

    You a repo once to get it onto your laptop. After that, commit whenever something works and at least once per session. Small commits are easier to undo.

    Never commit secrets

    From E3 on you'll have an API key in a file called .env. List it in before your first commit. A key pushed to a public repo is found by bots within minutes.

    git status shows what's changed and what's staged. Run it whenever you're unsure what a commit will include.

    5 · Reading errors

    Errors are instructions, not failures

    You'll see an error every few minutes as a beginner, and every hour as an expert. The skill is reading them. When Python fails it prints a : read it from the bottom up.

    Traceback (most recent call last):
  File "/Users/you/code/research-assistant/hello.py", line 5, in <module>
    print(f"Hello from the {nme}!")
                            ^^^
NameError: name 'nme' is not defined. Did you mean: 'name'?
    1. Last line first: the kind of error (NameError) and what went wrong. Python even suggests the fix.
    2. Then the file and line number: hello.py, line 5. In longer tracebacks, look for the lines in your own files, not in packages.
    3. Then the code itself, with ^^^ under the problem.
    You seeIt usually means
    command not foundThe program isn't installed, or the terminal was opened before you installed it
    No such file or directoryWrong folder, or a typo in the name. Run pwd and ls
    SyntaxErrorA typo in the code: a missing bracket, quote or colon, often on the line before the one shown
    ModuleNotFoundErrorA package isn't installed in this project. uv add it, and run with uv run
    IndentationErrorThe spaces at the start of a line don't line up. Python uses them to group code

    Asking for help, from a person or an AI assistant: paste the whole error, the command you ran, the folder you ran it in, and the file. "It doesn't work" gets guesses. The full error usually gets the fix in one reply.

    Lab · on your laptop

    Set up your machine and ship your first program

    Do these steps in order. Each one shows what you should see. If you see something else, check the "If it breaks" box at the end before searching the web.

    Time 60–90 minAPI cost noneYou need a Mac or Windows laptop, admin rights, a GitHub account
    1. 1

      Open a terminal

      Press Cmd + Space, type Terminal and press Enter. You'll see a line ending in %: that's the prompt, waiting for a command.

      Press the Windows key, type Terminal and press Enter. It opens PowerShell. You'll see a line ending in >: that's the prompt, waiting for a command.

    2. 2

      Install uv, which installs Python for you

      Terminal
      curl -LsSf https://astral.sh/uv/install.sh | sh
      Terminal
      powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

      Close the terminal and open a new one, so it can find the new program. Then check it worked:

      Terminal
      uv --version

      Expected output

      uv 0.11.32

      Any version number is fine. Yours may be newer.

    3. 3

      Install Python

      Terminal
      uv python install 3.13

      Expected output

      Installed Python 3.13.x in 2.31s

      The last number and the time will differ. You don't need to uninstall any Python you already have.

    4. 4

      Install VS Code and its Python extension

      Download VS Code from code.visualstudio.com and install it. Open it, click the Extensions icon in the left bar (four squares), search for Python and install the one published by Microsoft.

      From now on, use VS Code's built-in terminal: menu Terminal → New Terminal. It works the same as the one you opened in step 1.

    5. 5

      Install git and tell it who you are

      Type this in the terminal. If git is missing, your Mac offers to install the developer tools: click Install, wait, then run it again.

      Terminal
      git --version

      Install git with the command below, or download it from git-scm.com. Then close and reopen the terminal and check it.

      Terminal
      winget install --id Git.Git -e --source wingetgit --version

      Expected output

      git version 2.x.x

      Tell git your name and email. They appear on every commit you make, so use the email you'll use for GitHub.

      Terminal
      git config --global user.name "Your Name"git config --global user.email "you@example.com"
    6. 6

      Create your project on GitHub

      Sign up or log in at github.com. Click + → New repository. Name it research-assistant, choose Public, tick Add a README file, and click Create repository.

      This is the repo you'll grow for all 12 modules, and the one you'll show people at the end.

    7. 7

      Download it to your laptop

      In VS Code's terminal, make a folder for your code, go into it, and clone the repo. Replace YOUR-USERNAME with your GitHub username.

      Terminal
      mkdir codecd codegit clone https://github.com/YOUR-USERNAME/research-assistant.git

      Expected output

      Cloning into 'research-assistant'...
remote: Enumerating objects: 3, done.
...

      Now open it in VS Code: File → Open Folder…, then pick code/research-assistant. Open a new terminal (Terminal → New Terminal). It starts inside the project folder.

    8. 8

      Turn it into a Python project

      Terminal
      uv init --python 3.13

      Expected output

      Initialized project `research-assistant`

      uv added pyproject.toml (the project's settings), .python-version and a sample main.py. Delete main.py; you'll write your own file.

      Now create a file called .gitignore (with the dot) in VS Code: File → New File, then save it with that name. Add these lines, which keep the private environment and your future API keys out of GitHub:

      .gitignore
      .venv/__pycache__/.env
    9. 9

      Write and run your first program

      Create hello.py and type this in. Typing it, rather than pasting, helps you notice the details: quotes, brackets, the f before the string.

      hello.py
      """E1 lab: your first Python program."""import platform name = "research assistant"print(f"Hello from the {name}!")print(f"Python {platform.python_version()} on {platform.system()}")
      Terminal
      uv run hello.py

      Expected output

      Using CPython 3.13.x
Creating virtual environment at: .venv
Hello from the research assistant!
Python 3.13.x on Darwin

      The first two lines appear only the first time. On Windows the last word is Windows. Now change name to your own name, save, and run it again.

    10. 10

      Save a snapshot and send it to GitHub

      Terminal
      git add .git commit -m "Add hello.py and project settings"git push

      Expected output

      [main 5d6e7f8] Add hello.py and project settings
 4 files changed, 17 insertions(+)
...
To https://github.com/YOUR-USERNAME/research-assistant.git
   1a2b3c4..5d6e7f8  main -> main

      The first time you push, VS Code asks to sign in to GitHub: click Allow and finish in the browser. Refresh your repo page on GitHub: hello.py is there. .venv is not, which is what .gitignore is for.

    If it breaks

    uv: command not found / The term 'uv' is not recognized
    The terminal was open before uv was installed. Close every terminal, and VS Code itself, then open a new one.
    fatal: not a git repository
    You're in the wrong folder. Run pwd. You should be inside research-assistant; open that folder in VS Code and use a new terminal.
    error: Failed to spawn: `hello.py`
    uv can't find the file. Check you saved it (a dot on the tab means unsaved), that it's named exactly hello.py, and that ls lists it.
    remote: Support for password authentication was removed
    GitHub doesn't take your password in the terminal. Push from VS Code's own terminal, or click Sync Changes in VS Code's Source Control panel, and sign in when asked.

    3 common setup mistakes

    1

    Running commands in the wrong folder

    What it looks like
    "No such file or directory" for a file you can see in VS Code, or "not a git repository".
    Fix
    Open the project folder in VS Code and use its terminal. When in doubt, pwd.
    2

    Committing secrets or the .venv folder

    What it looks like
    Thousands of package files on GitHub, or worse, an API key in a public repo.
    Fix
    Write .gitignore before the first commit. If a key is ever pushed, revoke it in the provider's console straight away; deleting the commit isn't enough.
    3

    Skimming the error

    What it looks like
    Reinstalling Python, or asking for help with "it doesn't work", when the last line said exactly what was wrong.
    Fix
    Read the last line, then the line number in your file. Share the whole error when you ask.
