Prompts and structured output: answers your code can use

A chatbot can reply in free text. Most AI features can't: the answer has to go into a database, a dashboard or the next step of an agent. This module covers writing prompts as , showing examples, and getting back JSON in an exact shape with and . Then you check that the content is right, not just the shape. You'll build an extractor that turns any article into checked data for the research assistant.

Words with a dotted underline, like , are technical terms. Tap one for a plain-English definition.

What you'll build

A script that reads an article and saves its title, key claims with supporting quotes, and sources, after checking every quote is really in the article:

    1 · Prompt templates
    
    
    Write the prompt once, fill it in each time
    
    
    In an app, the instructions stay the same and the material changes: a different article, question or customer each time. Write the prompt once with a gap, and let the code fill it in.
    
  
    
  
    A template
    PROMPT = """Summarise the article below for a busy product manager. Rules:- At most 3 bullet points.- Give any numbers exactly as the article does.- If the article reaches no clear conclusion, say so. <article>{article}</article>""" prompt = PROMPT.format(article=text)   # fill the gap for this article
    
  
    
    
    Wrap the material in tags
     like <article> mark where pasted content starts and ends, so the model doesn't mistake a sentence in the article for an instruction to follow. Module 9 explains why that matters for security.
    
    
    Stable parts first
    Put the fixed instructions before the changing material. It reads more clearly, and it's what prompt caching needs to save money (module 8).
    
  
    
  
    .format() fills in {article}. An f-string would try to fill the gap when the template is written, before you have an article.
    

    



    
  
    
    
    2 · Clear instructions
    
    
    Say exactly what you want, and what to do when it's unclear
    
    
    Models follow instructions closely, including vague ones. Most prompt problems are missing details: how many, how long, in what form, and what to do when the material doesn't fit.
    
  
    
  
    
    
    
      
    VagueSpecific
    
      
        
    Summarise this article.Summarise this article in at most 3 bullet points for a product manager.
    
        
    List the key claims.List the 3 to 5 most important factual claims, each in one sentence.
    
        
    Include sources.For each claim, copy the exact words from the article that support it.
    
        
    (nothing)If the article cites no sources, return an empty list. Don't invent any.
    
          
    
    
  
    
  
    Giving the reason helps too: "so a reviewer can check each claim quickly" tells the model what matters when the rules don't cover a case.
    

    



    
  
    
    
    3 · Few-shot examples
    
    
    Show, don't only tell
    
    
     are worked examples in the prompt. A model copies their format, length and style more reliably than it follows a description of them.
    
  
    
  
    Few-shot examples, added to the prompt
    EXAMPLES = """Two examples of the claims and quotes I want: <example>Article: The council approved a new cycle lane on Main Street, costing 2 million pounds.Claim: The council approved a 2 million pound cycle lane on Main Street.Quote: approved a new cycle lane on Main Street, costing 2 million pounds</example> <example>Article: Sales rose 4% in March, the company said, after a weak February.Claim: The company reported 4% sales growth in March.Quote: Sales rose 4% in March</example>"""
    
  
    
    
    One to three is enough
    Each example is sent, and paid for, with every request.
    
    
    Make them differ
    If every example is about money, the model may think every claim should be. Vary the topic, and keep the form the same.
    
    
    Keep them correct
    A mistake in an example gets copied faithfully. Examples teach more strongly than rules do.

    4 · Getting JSON back
    
    
    Ask nicely, or have the API guarantee it
    
    
    Asking for JSON in the prompt usually works, and "usually" isn't good enough when your code breaks on the exceptions. Structured outputs make the API itself constrain the reply to your .
    
  
    
  
    
    
    
      
    ApproachWhat can still go wrong
    
      
        
    "Reply in JSON" in the promptText before the JSON, a missing field, a list where you wanted objects. Your parsing code breaks now and then.
    
        
    Structured outputs: messages.parse(…, output_format=YourClass)The reply always parses and fits the shape. The content can still be wrong: an invented quote is still a string.
    
        
    Structured outputs plus checks in your codeWhat's left is what your checks don't cover. This is what the lab builds.

    5 · Pydantic
    
    
    Describe your data as a class
    
    
    Pydantic lets you write the shape of your data as a Python class with typed fields. It checks data against the class and tells you exactly what doesn't fit, by field name. The Anthropic SDK reads the same class to build the schema for structured outputs.
    
  
    
  
    Try it in uv run python (after lab step 1)
    from pydantic import BaseModel, ValidationError class Claim(BaseModel):    claim: str    quote: str item = Claim.model_validate_json('{"claim": "Sales rose 4%", "quote": "Sales rose 4% in March"}')print(item.claim)                     # Sales rose 4% try:    Claim.model_validate_json('{"claim": "Sales rose"}')except ValidationError as error:    print(error)                      # 1 validation error for Claim                                      # quote                                      #   Field required [type=missing, ...]
    
  
    That message is a . Messages like it make good retry feedback: they name the field and the problem. You'll use Pydantic again for tool inputs (E5) and web APIs (E9).
    

    



    
  
    
    
    6 · Check, then retry
    
    
    The right shape isn't the same as the right answer
    
    
    Structured outputs guarantee the format. Whether the claims are true and the quotes real is still on you. Write checks in code for the rules you can state, and when one fails, send the problem back.
    
  
    
  
      
    
    1. Check what code can check. Each quote appears in the source word for word. Counts are in range. Dates parse. Every number appears in the source.
      2. 
    
    2. Retry with the specific problem. "This quote is not in the article: '…'" works better than "try again". This is .
      3. 
    
    3. Limit the attempts. Two or three, then fail with a clear error. Endless retries hide a broken prompt and run up the bill.
      4. 
    
    4. Count the failures. If 1 in 10 needs a retry, the prompt needs work. These checks are also your first evals (module 10, E8).

    3. 3
      Write the extractor
      Create extract.py. The Pydantic classes describe the data you want, and the template holds the instructions. check covers what a schema can't, and extract asks again when a check fails.
      extract.py
      """E4 lab: turn an article into checked, structured data. Run it with:    uv run extract.py article.txt"""import sysfrom pathlib import Path import anthropicfrom dotenv import load_dotenvfrom pydantic import BaseModel load_dotenv() MODEL = "claude-haiku-5-5"client = anthropic.Anthropic()  class Claim(BaseModel):    claim: str  # the claim, in one sentence    quote: str  # the exact words in the article that support it  class Extract(BaseModel):    title: str    claims: list[Claim]    sources: list[str]  # people, organisations or documents the article cites  PROMPT = """Extract the key facts from the article below. Rules:- title: the article's headline, or a short title if it has none.- claims: the 3 to 5 most important factual claims. Write each claim in one sentence,  and copy the exact words from the article that support it into quote.- sources: every person, organisation or document the article cites. Use an empty list if none. <article>{article}</article>"""  def check(result, article):    """Rules the schema can't enforce. Returns a list of problems; an empty list means all good."""    problems = []    if not 3 <= len(result.claims) <= 5:        problems.append(f"There are {len(result.claims)} claims. Give 3 to 5.")    text = " ".join(article.split())  # ignore differences in line breaks and spacing    for item in result.claims:        if " ".join(item.quote.split()) not in text:            problems.append(f"This quote is not in the article word for word: {item.quote!r}")    return problems  def extract(article, attempts=2):    """Ask for structured data, check it, and ask again with the problems listed if it fails."""    messages = [{"role": "user", "content": PROMPT.format(article=article)}]    for attempt in range(1, attempts + 1):        response = client.messages.parse(            model=MODEL,            max_tokens=4000,            messages=messages,            output_format=Extract,  # the API guarantees JSON in this shape            output_config={"effort": "low"},        )        if response.stop_reason != "end_turn":  # cut off or declined: no complete answer            raise RuntimeError(f"The model stopped early ({response.stop_reason}).")        result = response.parsed_output  # an Extract object, already validated        problems = check(result, article)        if not problems:            print(f"Checks passed on attempt {attempt}.")            return result        print(f"Attempt {attempt}: {len(problems)} problem(s). Asking again.")        messages.append({"role": "assistant", "content": response.content})        messages.append({"role": "user", "content": "Fix these problems and answer again:\n" + "\n".join(problems)})    raise ValueError("Still failing the checks:\n" + "\n".join(problems))  def main(path):    article = Path(path).read_text(encoding="utf-8")    result = extract(article)    output = result.model_dump_json(indent=2)    print(output)    Path("extract.json").write_text(output, encoding="utf-8")    print("Saved to extract.json")  if __name__ == "__main__":    main(sys.argv[1] if len(sys.argv) > 1 else "article.txt")
      • Claim and Extract are the schema. The SDK turns them into a JSON schema, and the API guarantees the reply fits it.
      • PROMPT is a template: rules first, then the article inside <article> tags.
      • check tests what the schema can't: how many claims there are, and whether each quote is really in the article.
      • extract sends the problems back and asks again, at most twice, then gives up with a clear error.

    Learn from others
    
    
    3 common structured-output mistakes
    
  
    
  
    
    
    1
    Parsing free text with string tricks
    
      
    What it looks like
    Code that splits the reply on "Title:" and newlines, and breaks the first time the model words it differently.
    
      
    Fix
    Use structured outputs with a Pydantic class, and read parsed_output.
    
    
    2
    Treating valid JSON as a correct answer
    
      
    What it looks like
    A dashboard full of neatly formatted claims, some of which no source ever made.
    
      
    Fix
    Add grounding checks for anything you can check in code, and review a sample by hand.
    
    
    3
    Retrying forever, or failing silently
    
      
    What it looks like
    A loop that retries until it passes and quietly costs ten times as much, or bad data saved because the error was caught and ignored.
    
      
    Fix
    Two or three attempts with feedback, then a clear error, and count how often it happens.
