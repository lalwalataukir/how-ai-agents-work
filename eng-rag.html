Embeddings and RAG: answer from your own documents

Claude knows what it learned in training, not what's in your notes. fixes that: find the passages of your documents that match a question, put them in the prompt, and have the model answer from them with citations. This module covers , chunking, vector search with Chroma, citations, and the ways RAG fails. You'll build a tool that answers questions over your own PDFs and notes.

1 · Why RAG

    
The model hasn't read your notes

    
To answer from your documents, the model has to see them. You can send everything, or send only the parts that matter. RAG is the second way.

  

  

    
Send everything
Paste the documents into the prompt. Simple and exact, and fine for a few pages. But every question pays for every page again, and 500 pages won't fit or will cost too much.

    
Train it in
Fine-tuning changes how a model writes, not reliably what it knows, and it can't cite a page. E11 covers when it's worth it.

    
Retrieve, then answer
Find the few passages that match the question and send only those. Cheap per question, works for thousands of files, and every fact can point to its page.

  

  
    
    
  1. Index, once: read each file, cut it into chunks, turn each chunk into an embedding, and store them.
    2. 
    
  2. Retrieve, per question: turn the question into an embedding and find the closest chunks.
    3. 
    
  3. Generate: send those chunks and the question to Claude, which answers from them and cites each one.
    4. 
  

  
This is the context engineering of module 8 in code: decide what the model sees, and nothing more. It also answers module 1's question of how an agent knows things it was never trained on.

2 · Embeddings

    
Meaning as a list of numbers

    
An  turns any text into a fixed-length list of numbers, 384 of them for the model Chroma uses. Texts that mean similar things get similar lists, even when they share no words.

  

  
The gap between two embeddings is a : 0 means the same meaning, around 1 means unrelated. These are real distances from the lab, for the question "How much will I pay if I bring a book back late?":

  

    

      
Handbook sectionDistanceWhy

      
        
Late returns and lost items0.25About charges for late books, though it never says "pay" or "bring back"

        
Borrowing0.50Related: loan periods and renewals

        
E-books and audiobooks0.56Loosely related: borrowing, again

        
(any section, for "What is the capital of France?")0.97Nothing to do with the handbook

      
    

  

  

    
A separate model
Embeddings come from their own model, not from Claude. Chroma's default, all-MiniLM-L6-v2, is small, free and runs on your laptop, so the lab needs no second API key. Anthropic doesn't make embedding models; hosted ones such as Voyage AI's are stronger on hard cases.

    
Same model for both sides
Chunks and questions must be embedded by the same model. Change the model and you must index everything again, because the numbers from two models can't be compared.

  







  

    
3 · Chunking

    
Cut documents into the right-sized pieces

    
Retrieval returns , not files, so how you cut decides what can be found. Each chunk gets one embedding, which blends everything in it.

  

  

    

      
Chunk sizeWhat happensIn the demo

      
        
Small (250 characters)Precise matches, but a fact split across two chunks may need both17 chunks. "Connect to Wi-Fi" finds the Wi-Fi sentence first, at 0.55

        
Medium (500, the lab's size)About one section each: a good start for notes and articles9 chunks. The late-fee section comes first, at 0.25

        
Large (1,500)Each chunk mixes many topics, distances bunch together, and every question sends a lot of text2 chunks, all distances between 0.56 and 0.74

      
    

  

  

    
Follow the structure
Cut at paragraph breaks, keep a heading with the text under it, and cut long paragraphs at a full stop, never mid-sentence.

    
Keep where it came from
Store the file and page with every chunk. Without them, the answer can't cite anything.

    
Overlap, if facts get split
Many splitters repeat a little text between neighbouring chunks so a fact on the boundary survives. Keeping paragraphs whole does the same job for most notes.

4 · Vector search

    
Find the closest chunks

    
A  stores each chunk with its embedding and details, and finds the ones closest to a question fast. Chroma runs inside your Python program and saves to a folder: nothing to sign up for.

  

  
Asking Chroma for the 4 closest chunks
found = notes.query(query_texts=["How much will I pay if I bring a book back late?"], n_results=4)for text, meta, distance in zip(found["documents"][0], found["metadatas"][0], found["distances"][0]):    print(round(distance, 2), meta["source"], meta["page"], text[:40])

  

    
: how many
The lab sends the 4 closest. Too few and a two-part question misses half its answer; too many and the prompt fills with noise you pay for.

    
A distance cut-off
Something is always closest, even for nonsense. MAX_DISTANCE = 0.75 drops chunks too far away to help, and when nothing is left, the lab answers without calling Claude.

  







  

    
5 · Citations

    
Prompt with sources, answer with citations

    
The chunks go into the prompt inside tags that carry their file and page. The system prompt sets three rules: answer only from the sources, cite each fact, and say so when the sources don't cover the question.

  

  
What Claude receives (the user message)
<sources><source file="library-handbook.md" page="1">## Late returns and lost itemsSince 1 March 2026 there are no charges for late children's books. For adult items...</source><source file="library-handbook.md" page="1">## BorrowingYou can borrow up to 12 items at a time...</source></sources> Question: How much will I pay if I bring a book back late?

  
Citations make answers checkable. A  answer can still be wrong, but anyone can open the page it cites and see. E8 turns "every fact has a citation" into a check that runs on every change. Claude also has a built-in citations feature for documents sent whole, which returns the exact passage for each claim.







  

    
6 · When RAG fails

    
Most bad answers are bad retrieval

    
When an answer is wrong, look at what retrieval returned before you touch the prompt. In most RAG failures, the model was never shown the right text.

  

  

    

      
FailureWhat it looks likeWhat helps

      
        
"How do I get online?" never reaches the Wi-Fi sectionRephrase the question, raise k, add keyword search alongside vectors, or use a stronger embedding model

        
Not in the documents"Who founded the library?" still retrieves the closest chunks, at 0.64A system prompt that says "say you couldn't find it", and an eval case that checks it does

        
Answer spread across many chunks"Summarise all my notes" gets 4 chunks of 500A different design: summarise file by file, then combine

        
Stale indexYou edited a file but answers quote the old versionIndex again after changes; the lab replaces a file's chunks each time

        
Bad text from PDFsScanned pages give no text; tables come out jumbledOCR scanned files; check the chunk count for each file

  3. 3
    Write rag.py
    Create rag.py. It does the two halves of RAG: indexing (read, chunk, store) once, and answering (search, then ask Claude) for every question.
    rag.py
    """E6 lab: ask questions over your own notes and PDFs, and get answers with citations. Run it with:    uv run rag.py index docs                  # read every file in docs/ into the database    uv run rag.py search "late fees"          # see what retrieval finds (free: no model call)    uv run rag.py ask "How much is the fine for a late book?""""import sysfrom pathlib import Path import anthropicimport chromadbfrom dotenv import load_dotenvfrom pypdf import PdfReader load_dotenv() MODEL = "claude-haiku-5-5"PRICE_IN, PRICE_OUT = 0.10, 0.50  # dollars per million tokens, for this modelCHUNK_SIZE = 500     # most characters in one chunk, about 125 tokensTOP_K = 4            # how many chunks to give the modelMAX_DISTANCE = 0.75  # skip chunks further than this from the question (0 = same meaning, 1 = unrelated)SYSTEM = (    "Answer the question using only the sources below. After each fact, cite the source it came from "    "as [file, page N]. If the sources don't contain the answer, say you couldn't find it in the notes. "    "Answer in at most 150 words.") client = anthropic.Anthropic()db = chromadb.PersistentClient(path=Path(__file__).parent / "chroma")  # a folder next to this filenotes = db.get_or_create_collection("notes", configuration={"hnsw": {"space": "cosine"}})  def read_file(path):    """Return a list of (page number, text). A text or Markdown file counts as one page."""    if path.suffix.lower() == ".pdf":        return [(number, page.extract_text() or "") for number, page in enumerate(PdfReader(path).pages, 1)]    return [(1, path.read_text(encoding="utf-8"))]  def chunk_text(text, size=CHUNK_SIZE):    """Split text into chunks of at most `size` characters, keeping paragraphs and sentences whole."""    pieces, heading = [], ""    for paragraph in text.split("\n\n"):        lines = paragraph.strip().split("\n")        if lines[0].startswith("#"):  # a Markdown heading: keep it with the text below it            heading = (heading + "\n" + lines.pop(0).strip()).strip()        paragraph = " ".join(" ".join(lines).split())  # tidy line breaks and spaces        if not paragraph:            continue        if heading:            paragraph, heading = heading + "\n" + paragraph, ""        while len(paragraph) > size:  # too long: cut at the last sentence end that fits            cut = paragraph.rfind(". ", 0, size)            cut = cut + 1 if cut > 0 else size            pieces.append(paragraph[:cut].strip())            paragraph = paragraph[cut:].strip()        if paragraph:            pieces.append(paragraph)    chunks = []    for piece in pieces:  # join short pieces until a chunk is full        if chunks and len(chunks[-1]) + 1 + len(piece) <= size:            chunks[-1] += "\n" + piece        else:            chunks.append(piece)    return chunks  def index_file(path, folder):    """Chunk one file and store the chunks. Indexing a file again replaces its old chunks."""    source = path.relative_to(folder).as_posix()    notes.delete(where={"source": source})    count = 0    for page, text in read_file(path):        chunks = chunk_text(text)        if chunks:            notes.add(                ids=[f"{source}:{page}:{n}" for n in range(len(chunks))],                documents=chunks,  # Chroma turns each chunk into an embedding as it stores it                metadatas=[{"source": source, "page": page} for _ in chunks],            )            count += len(chunks)    return count  def index_folder(folder):    """Index every .md, .txt and .pdf file in a folder and the folders inside it."""    folder = Path(folder)    total = 0    for path in sorted(folder.rglob("*")):        if path.suffix.lower() in (".md", ".txt", ".pdf"):            count = index_file(path, folder)            print(f"  {path.relative_to(folder)}: {count} chunks")            total += count    return total  def search(question, k=TOP_K):    """The k chunks closest in meaning to the question, skipping any that are too far away."""    if notes.count() == 0:        return []    found = notes.query(query_texts=[question], n_results=min(k, notes.count()))    hits = []    for text, meta, distance in zip(found["documents"][0], found["metadatas"][0], found["distances"][0]):        if distance <= MAX_DISTANCE:            hits.append({"source": meta["source"], "page": meta["page"], "text": text, "distance": round(distance, 2)})    return hits  def answer(question, hits):    """Ask Claude to answer the question from the retrieved chunks."""    if not hits:  # nothing close enough: say so, and don't pay for a model call        return "I couldn't find anything about that in your notes."    sources = "\n".join(        f'<source file="{hit["source"]}" page="{hit["page"]}">\n{hit["text"]}\n</source>' for hit in hits    )    response = client.messages.create(        model=MODEL, max_tokens=2000, system=SYSTEM, output_config={"effort": "low"},        messages=[{"role": "user", "content": f"<sources>\n{sources}\n</sources>\n\nQuestion: {question}"}],    )    cost = (response.usage.input_tokens * PRICE_IN + response.usage.output_tokens * PRICE_OUT) / 1_000_000    print(f"  [{response.usage.input_tokens} tokens in, {response.usage.output_tokens} out, ${cost:.5f}]\n")    return "".join(block.text for block in response.content if block.type == "text")  def show(hits):    for hit in hits:        preview = hit["text"].replace("\n", " ")[:70]        print(f"  {hit['distance']:.2f}  {hit['source']}, page {hit['page']}: {preview}...")  def main(args):    if len(args) == 2 and args[0] == "index":        total = index_folder(args[1])        print(f"Indexed {total} chunks. The database holds {notes.count()}.")    elif len(args) >= 2 and args[0] in ("search", "ask"):        question = " ".join(args[1:])        hits = search(question)        if hits:            show(hits)        else:            print("  Nothing close enough in your notes.")        if args[0] == "ask":            print(answer(question, hits))    else:        print(__doc__)  if __name__ == "__main__":    main(sys.argv[1:])
    • notes is a Chroma collection saved in the chroma folder next to rag.py. Cosine distance makes 0 mean "same meaning".
    • read_file returns text page by page, so every chunk knows its page for citations.
    • chunk_text keeps paragraphs whole, keeps each heading with the text under it, and cuts long paragraphs at a full stop.
    • index_file deletes a file's old chunks first, so indexing again after an edit doesn't leave stale copies.
    • search asks Chroma for the TOP_K closest chunks and drops any further away than MAX_DISTANCE.
    • answer puts the chunks in <source> tags with file and page, and skips the model call when nothing was close.

Learn from others

    
3 common RAG mistakes

  

  

    
1
Tuning the prompt when retrieval is the problem

      
What it looks like
Hours of prompt changes for a question whose answer was never in the chunks sent.

      
Fix
Print the retrieved chunks and distances first. If the answer isn't there, work on chunking, the question or k.

    
2
Chunks without sources

      
What it looks like
Answers that sound right but can't say where a fact came from, so nobody can check them.

      
Fix
Store the file and page with every chunk, pass them in the prompt, and require a citation per fact.

    
3
No way to say "not found"

      
What it looks like
A question the documents don't cover still gets a confident answer, built from loosely related chunks.

      
Fix
A distance cut-off, a system prompt rule to say when the sources don't answer, and test questions that check it.
