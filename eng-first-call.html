Your first LLM call: keys, messages, tokens and cost

A large language model is a web API like Wikipedia's in E2: you send a request and get JSON back. This module covers what goes in the request, what comes back, and what each call costs. You'll keep your safe, send a conversation through the , stream the reply, and handle the errors real apps meet. You'll build a chatbot for the research assistant that remembers the conversation and shows the cost of every turn.

Words with a dotted underline, like , are technical terms. Tap one for a plain-English definition.

What you'll build

A chatbot in your terminal that streams its answers and keeps a running total of what you've spent:

% uv run chat.py
You: What is retrieval-augmented generation, in two sentences?
Claude: Retrieval-augmented generation (RAG) has a model look up …
  [52 tokens in, 96 out, $0.00005 this turn, $0.00005 so far]

1 · API keys

    
The key is your account's password, and its credit card

    
Every request carries your API key. Whoever has it can spend your money, so it lives in one place only: a  on your laptop that git ignores.

  

  

    
Store it in .env
ANTHROPIC_API_KEY=sk-ant-… in a file called .env. load_dotenv() copies it into the environment, and the SDK finds it there by name.

    
Never in code or chats
Not in a .py file, not in a screenshot, not pasted into an AI assistant. Code gets committed and shared; .env doesn't.

    
Limit the damage
Set a monthly spending limit in the Console, use one key per project, and if a key leaks, delete it straight away and make a new one.

  







  

    
2 · The Messages API

    
Send a list of messages, get content blocks back

    
The  turns one function call into a web request. You choose a model, a limit on the reply's length, and the conversation so far: a list of dicts that take turns between "user" and "assistant", exactly the shape you met in E2.

  

  
The shape of every call
import anthropic client = anthropic.Anthropic()          # reads ANTHROPIC_API_KEYreply = client.messages.create(    model="claude-haiku-5-5",           # which model    max_tokens=1000,                     # the longest reply allowed, thinking included    system="You are a research assistant. Answer in at most 120 words.",    messages=[        {"role": "user", "content": "What is RAG?"},    ],)print(reply.content[-1].text)           # the answerprint(reply.stop_reason, reply.usage)   # why it stopped, and the token counts

  

    

      
In the replyWhat it holds

      
        
contentA list of blocks. text blocks hold the answer; thinking blocks hold the model's reasoning (hidden by default); tool_use blocks come in E5.

        
stop_reasonWhy it stopped: end_turn, max_tokens, tool_use or refusal. See .

        
usageinput_tokens and output_tokens: what you're billed for.

      
    

  

  
The API remembers nothing. It's : each request stands alone. A chatbot "remembers" because your code keeps the conversation in a list and sends all of it every time. Append the model's whole reply (response.content), not just its text, so the thinking blocks travel with it.

3 · System prompt and effort

    
Standing instructions, and how hard to think

    
Two settings shape every reply. The  says who the assistant is and what rules it follows.  says how much it should think first.

  

  

    
A good system prompt
States the role, the limits and what to do when unsure: "You are a research assistant. Answer in at most 120 words. If you are not sure about a fact, say so instead of guessing." Short and specific beats long and vague. Module 8 covers this in depth.

    
Effort, not temperature
Older tutorials set temperature. Current Claude models reject it. Use output_config={"effort": "low"} for chat and simple tasks, "medium" (Haiku's default) or "high" for harder reasoning.

  

  
Current models do some  before they answer, and decide for themselves how much. The thinking text is hidden by default, but its tokens are billed as output. That's why higher effort costs more even when the visible answer is the same length.







  

    
4 · Tokens and cost

    
You pay per token, in and out

    
Models read and write tokens, pieces of words. A rough guide is three tokens for every two English words. Each request is billed for the tokens it sends (input) and the tokens it gets back (output), and output costs five times as much.

  

  

    

      
ModelInput, per million tokensOutput, per million tokens1,000 chat turns*

      
        
Claude Haiku 5.5 (claude-haiku-5-5): fast and cheap, used in these labs$0.10$0.50$0.100

        
Claude Sonnet 5.5 (claude-sonnet-5-5): the everyday workhorse$2.00$10.00$2.000

        
Claude Opus 5.5 (claude-opus-5-5): the strongest reasoning$4.00$20.00$4.000

      
    

  

  
* Each turn 500 tokens in and 100 out. Prices as published in October 2026; check the pricing page before you plan a budget.

  

    
The formula
cost = (input_tokens × input price + output_tokens × output price) ÷ 1,000,000. The API reports both counts in usage on every reply, so your code can add up the cost as it goes.

    
Why conversations get expensive
Turn 10 re-sends turns 1 to 9 as input. Input tokens grow with every turn, even when the questions are short. Long chats, big documents and tool loops (E5) are where costs come from. Module 8 covers trimming and caching.

5 · Streaming

    
Show the first words in under a second

    
Without , your code waits until the whole reply is written, which can be many seconds. With it, words arrive as they're written. The total time is the same; the wait feels far shorter.

  

  
Streaming
with client.messages.stream(model="claude-haiku-5-5", max_tokens=1000, messages=messages) as stream:    for text in stream.text_stream:          # a few words at a time        print(text, end="", flush=True)    reply = stream.get_final_message()       # the complete reply, with usage

  
Stream anything a person waits for. For background jobs where nobody watches, such as extracting data from 500 articles, a plain messages.create is simpler.







  

    
6 · Errors and retries

    
Some errors are worth retrying, most aren't

    
The status codes from E2 apply here too. The SDK raises a named exception for each, and it already  the temporary ones (429, 500, 529 and dropped connections) twice, with growing waits, before your code sees them.

  

  

    

      
StatusSDK exceptionUsually meansRetry?

      
        
400BadRequestErrorSomething in the request is wrong: a bad parameter or message orderNo: fix the code

        
401AuthenticationErrorMissing or wrong API keyNo

        
402APIStatusErrorBilling: no credit, or the spending limit reachedNo

        
404NotFoundErrorModel name typo, or a model your account can't useNo

        
429RateLimitErrorToo many requests or tokens per minuteYes, after a wait

        
500, 529InternalServerError, OverloadedErrorA problem or heavy load on the API's sideYes, after a wait

        
noneAPIConnectionErrorYour internet, VPN or a timeoutYes

      
    

  

  
Catch the specific exceptions first and the general APIStatusError last, as the lab does. Also check stop_reason on every reply: a max_tokens reply is incomplete even though no error was raised.

  5. 5
    Write the chatbot
    Create chat.py. It keeps the whole conversation in messages, streams each reply, and works out the cost from the token counts the API returns.
    chat.py
    """E3 lab: a terminal chatbot that remembers the conversation and shows what each turn costs. Run it with:    uv run chat.py"""import anthropicfrom dotenv import load_dotenv load_dotenv()  # copies ANTHROPIC_API_KEY from the .env file into the environment MODEL = "claude-haiku-5-5"  # the cheapest model; try "claude-sonnet-5-5" for harder questionsPRICE_IN = 0.10  # dollars per million input tokens, for this modelPRICE_OUT = 0.50  # dollars per million output tokensSYSTEM = (    "You are a research assistant. Answer in at most 120 words. "    "If you are not sure about a fact, say so instead of guessing.") client = anthropic.Anthropic()  # finds ANTHROPIC_API_KEY by itself  def turn_cost(usage):    """Dollars for one request, from the token counts the API reports."""    return (usage.input_tokens * PRICE_IN + usage.output_tokens * PRICE_OUT) / 1_000_000  def ask(messages):    """Send the whole conversation, print the reply as it arrives, and return the full response."""    with client.messages.stream(        model=MODEL,        max_tokens=2000,        system=SYSTEM,        messages=messages,        output_config={"effort": "low"},  # less thinking: faster and cheaper for chat    ) as stream:        for text in stream.text_stream:            print(text, end="", flush=True)        return stream.get_final_message()  def main():    messages = []  # the conversation so far: the API remembers nothing between requests    total = 0.0    print(f"Chatting with {MODEL}. Type quit to stop.\n")    while True:        question = input("You: ").strip()        if question.lower() in ("quit", "exit"):            break        if not question:            continue         messages.append({"role": "user", "content": question})        print("Claude: ", end="")        try:            response = ask(messages)        except anthropic.AuthenticationError:            print("\nThe API key was rejected. Check ANTHROPIC_API_KEY in your .env file.")            break        except anthropic.APIConnectionError:            print("\nCould not reach the API. Check your internet connection and try again.")            messages.pop()  # forget the question that got no answer            continue        except anthropic.APIStatusError as error:  # 402, 429, 500 and others, after the SDK's own retries            print(f"\nThe API answered {error.status_code}: {error.message}")            messages.pop()            continue         # Keep the whole reply, not just its text, so the next request has the full conversation        messages.append({"role": "assistant", "content": response.content})        cost = turn_cost(response.usage)        total += cost        print(f"\n  [{response.usage.input_tokens} tokens in, {response.usage.output_tokens} out, "              f"${cost:.5f} this turn, ${total:.5f} so far]\n")        if response.stop_reason == "max_tokens":            print("  (The reply was cut off. Raise max_tokens for longer answers.)\n")        elif response.stop_reason == "refusal":            print("  (Claude declined to answer that one.)\n")     print(f"Session cost: ${total:.5f}")  if __name__ == "__main__":    main()
    • ask sends the whole conversation and prints the reply as it arrives.
    • main adds your question, then the full reply, to messages, so the next request carries the history.
    • The except blocks turn API errors into plain messages, most specific first. The SDK has already retried 429s and server errors twice by then.

Learn from others

    
3 common first-call mistakes

  

  

    
1
The key in the code

      
What it looks like
api_key="sk-ant-…" in a file that gets pushed to GitHub. Within hours, someone else is spending your credit.

      
Fix
Keep it in .env, check git status before every commit, and delete any key that has leaked.

    
2
Not watching the cost

      
What it looks like
A loop or long conversation re-sends thousands of tokens per call, and nobody notices until the bill arrives.

      
Fix
Log usage on every call, set a spending limit, and use the cheapest model that does the job.

    
3
Ignoring stop_reason

      
What it looks like
Answers that end mid-sentence get shown or saved as if complete, because max_tokens was too low for the thinking plus the answer.

      
Fix
Check stop_reason on every reply, and leave room in max_tokens for thinking.
