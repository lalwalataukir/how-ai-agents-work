1 · From script to web app

A server between the visitor and your key

A web app splits the work in two. The page runs in the visitor's browser; your code runs on a server you control. Only the server holds the API key, and the browser only ever talks to your server.

  1. BrowserThe page sends the question to /ask and shows whatever comes back.
  2. FastAPIChecks the question, applies the limits, and calls your agent. Runs inside , the web server.
  3. AgentThe same steps() from E7 to E8, now streaming, with only read-only tools.
  4. Claude and WikipediaCalled from your server, never from the browser.

2 · Streaming

Show progress at once, words as they come

An agent question takes several seconds. Waiting in silence feels broken; watching steps appear and words arrive feels fast. The total time is the same, but the drops a lot.

The agent yields

steps() already yields plan and tool events. Streaming each model call adds "text" events, one per piece of text.

FastAPI forwards

With response_class=EventSourceResponse, every event the function yields goes out at once as a : a line starting data:.

The page reads

fetch plus a stream reader picks up each event as it arrives and adds it to the page, as text, never as HTML.

3 · Limits

A public URL spends your money

Anyone who finds your app can send it questions, and every question costs you. Limits decide how much damage one visitor, a bot or a bug can do.

LimitIn the labStops
Input size3 to 500 characters, checked by Pydantic (422)Huge prompts that cost a lot per question
5 questions a minute per visitor (429)One visitor or script hammering the app
Daily cost capDAILY_BUDGET, $0.50 by default (503)Many visitors adding up
Per-question limitsE7's MAX_CALLS and MAX_COSTOne question looping
Fewer toolsOnly search_wikipedia and read_pageStrangers reading your notes or writing files
Console spend limitSet in E3, outside your codeEverything else, including your own bugs

Memory isn't storage. The lab counts questions and dollars in Python variables, so a restart resets them, and a free host restarts often. That's fine for a demo. A busy app would keep the counts in a database such as Redis, and the Console's spend limit stays the backstop either way.

4 · Prompt caching

Don't pay full price for the same text twice

Every call in the loop starts with the same tools and system prompt, then the conversation so far. lets the API keep that start for five minutes. A request that begins with exactly the same text reads it from the cache instead.

Input tokens that are…Cost, compared with normal inputClaude Haiku 5.5, per million
New1×$0.10
Written to the cache1.25×$0.125
Read from the cache0.1×$0.01

Where to mark it

One breakpoint on the system prompt caches the tools and instructions every visitor shares. The top-level cache_control caches each conversation as it grows.

What breaks it

Any change before a breakpoint: a time or date in the system prompt, tools in a different order, a different model. Then cache_read_input_tokens stays at 0.

The small print

Claude Haiku 5.5 caches prompts of 512 tokens or more. Entries last five minutes, and each read resets the clock, so steady traffic keeps them warm.

For the demo's question, caching cuts the input cost by about 60% and the total by about half. Module 8 covers the context design that makes caching work.

6 · Hosting

Render's free tier, and what it costs you

A host runs your server on the internet and gives it an address. Render connects to your GitHub repo, installs your project with uv, starts it, and redeploys on every push to main.

What free gets you

A web service with a public onrender.com address, 512 MB of memory and 750 free instance hours a month, enough for one app running all month.

The catches

It sleeps after 15 minutes without visitors and takes about a minute to wake. Files written on the server vanish on every restart and deploy. It's for demos, not production.

    """E9 lab: the research assistant as a web app, with streaming, rate limits and a daily cost cap. Run it on your laptop with:    uv run uvicorn app:app --reloadthen open http://127.0.0.1:8000"""import osimport timefrom collections import defaultdict, dequefrom datetime import datefrom pathlib import Path from fastapi import Depends, FastAPI, HTTPException, Requestfrom fastapi.responses import FileResponsefrom fastapi.sse import EventSourceResponsefrom pydantic import BaseModel, Field import agent MAX_PER_MINUTE = 5  # questions per visitor per minuteDAILY_BUDGET = float(os.environ.get("DAILY_BUDGET", "0.50"))  # dollars a day, for all visitors togetherWEB_TOOLS = ["search_wikipedia", "read_page"]  # a public site gets no private notes and no saving app = FastAPI()recent = defaultdict(deque)  # visitor -> times of their recent questionsspent = {"day": "", "dollars": 0.0}  # resets each day, and whenever the server restarts  class Question(BaseModel):    question: str = Field(min_length=3, max_length=500)  # FastAPI rejects anything else with a 422  def check_limits(request: Request):    """Runs before every question. Raising an HTTPException turns the request away."""    now, times = time.time(), recent[request.client.host]    while times and now - times[0] > 60:        times.popleft()  # forget questions older than a minute    if len(times) >= MAX_PER_MINUTE:        raise HTTPException(429, "Too many questions. Wait a minute and try again.")    if spent["day"] != date.today().isoformat():        spent.update(day=date.today().isoformat(), dollars=0.0)    if spent["dollars"] >= DAILY_BUDGET:        raise HTTPException(503, "Today's budget is used up. Try again tomorrow.")    times.append(now)  @app.get("/")def home():    return FileResponse(Path(__file__).parent / "static" / "index.html")  @app.get("/health")def health():    return {"ok": True}  # the host checks this to know the app is up  @app.post("/ask", response_class=EventSourceResponse, dependencies=[Depends(check_limits)])def ask(body: Question):    """Stream the agent's events to the page as they happen: plan, tools, text, done."""    start, first_text = time.perf_counter(), None    for event in agent.steps(body.question, [], tools=WEB_TOOLS, approve=lambda name, args: False):        if event["type"] == "text" and first_text is None:            first_text = time.perf_counter() - start  # what the visitor feels as speed        if event["type"] == "done":            spent["dollars"] += event["cost"]            event["seconds"] = round(time.perf_counter() - start, 1)            event["first_text"] = round(first_text or event["seconds"], 1)        yield event
    • Question is a Pydantic model: FastAPI rejects anything that isn't 3 to 500 characters with a 422, before your code runs.
    • check_limits runs before every question. It keeps each visitor's recent times and turns away a sixth question in a minute (429), and stops all questions once today's spending reaches DAILY_BUDGET (503).
    • ask streams the agent's events as , offering only the two read-only Wikipedia tools, refusing every approval, and adding timings to the last event.
    • /health answers instantly, so the host can tell the app is up.

If it breaks

bash: line 1: uvicorn: command not found
Start the command with uv run, and make sure uv add uvicorn put it in pyproject.toml and uv.lock.
==> No open ports detected, continuing to scan...
The app is listening in the wrong place. Use --host 0.0.0.0 --port $PORT exactly; a fixed port number won't work on Render.
anthropic.AuthenticationError: Error code: 401 (in Render's logs)
The key is missing or mistyped in Render's Environment settings. Save it there, then redeploy.
Too many questions. Wait a minute and try again. (for everyone at once)
All visitors look like one. Add --forwarded-allow-ips "*" to the start command so the app sees each visitor's address.

Glossary

Learn from others

3 common shipping mistakes

1

The API key in the browser

What it looks like
The page calls the Claude API directly with the key in its JavaScript, where anyone can read it and spend your money.
Fix
The browser talks only to your server. The key lives in the host's environment variables.
2

No limits on a public URL

What it looks like
A bot finds the app overnight, and the morning brings a bill.
Fix
Input limits, a per-visitor rate limit, a daily cap in code, and a spend limit in the Console.
3

A timestamp in the system prompt

What it looks like
"Today is 20 October, 09:41:07" at the top of every prompt, so the cache never matches and every token is paid in full.
Fix
Keep the start of the prompt identical; put anything that changes after the cache breakpoints.
